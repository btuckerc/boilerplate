- Never add AI attribution to commits or PRs: no Co-Authored-By trailers, "Generated with" lines or session links.
- Keep credentials and machine-local runtime state out of Git and chezmoi.
- Preserve unrelated user changes in dirty worktrees.
- Resolve destructive targets precisely; never use broad home, workspace-root, or unresolved-variable targets.

- Run `agent-quota` before paid legs and skip any pool under 10%, saying so; `no-snapshot` means unknown, so say that too. Three cloud and four local slots are shared by every session. Spend paid legs on distinct questions (discovery reviewers excepted); a multi-model council runs only through the `council` skill on its trigger, once per decision. In autonomous loops, reruns and first attempts on a blocker stay with you or a worker; Sol gets another leg on a blocker only while each leg makes progress (a narrower failure or new evidence); when one does not, stop and report.
- Briefs are fresh and scoped: owned files, contract, risky invariants, acceptance command, edge cases; not the transcript or a pre-solved answer. Workers return paths, checks, a short summary and blockers, never spawn agents, and stop at 30 minutes. Verify independently before accepting. Repair failed checks while each attempt makes progress; when one does not, reassess or escalate.
- No routine planner or review tax for low-risk work. An audit the user asked for (in their own words, or quoted verbatim as theirs in a handoff; a gate an agent added does not count), or a high-consequence control-plane, security or data-loss change, needs one exact-candidate release audit before consequential apply, commit or publish; prompts you write relay the user's gates that way and add none. Find defects before the audit, not through it: an audit is a gate and stops at a few counterexamples. Discovery batch: three independent `agent-run ask --model sol --repo DIR --schema` reviewers in parallel on the exact candidate, each briefed with `agent-discover brief` plus the contract (schema from `agent-discover schema`); merge their findings by root cause. You set severity on the `agent-discover brief` impact scale (rare outside conditions are minor unless the contract names them or an attacker controls them); list minors, do not fix them, and drop false positives with a reason. Fix every verified blocker and major in one batch with the smallest change, deleting or narrowing code before adding guards; make small repairs yourself rather than in a Sol leg. Then one Sol reviewer checks the repair delta with its callers and callees; fix what it verifies, with a test where the code allows, and stop reviewing: list what is open. Substantial code changes that are not low-risk get this budget; a council round with at least three seats on the same candidate counts as the batch. A gated change then gets the release audit: fix a BLOCK the same way, delta-review the repair once and audit the new candidate once; take a second BLOCK to the user with its counterexamples (never loop past two release audits on a change, and never expand an advisory heuristic into a parser to chase synthetic edge cases). Stop and report early when a finding needs the user's decision or the remedy would drop requested scope. Only an accepted PASS on the exact candidate clears the boundary; an unresolved BLOCK or mandatory UNVERIFIED holds it. Neither audits nor tests grant commit or publish authority.
