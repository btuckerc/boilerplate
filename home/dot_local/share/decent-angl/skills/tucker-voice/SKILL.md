# Tucker’s voice

Use this as an editorial reference, not an impersonation checklist. Read the
[voice reference and examples](references/voice.md) before drafting. The reference
is self-contained; no access to old OMP sessions or a particular project is needed.

## Apply only to the requested writing

- Explicit invocation activates this reference for the requested draft and its
  revisions, not every later task or ordinary assistant response. Do not load it
  automatically because a task contains the word “draft.”
- Keep the existing `/draft` skill’s purpose separate: it develops executable task
  handoffs. This skill shapes prose. It does not select models or launch workers.
- Use the user’s requested audience, medium, length and purpose. Infer ordinary
  details from the current task; ask only when a missing fact changes the message.
- Current wording preferences and corrections override this dated reference.
  Direct user examples outrank assistant-written copy and inferred style rules.

## Draft

1. Identify the actual point, supported personal reason, and concrete example.
   Do not invent a frustration, habit, result, relationship or feeling to make
   the copy sound personal.
2. Write as Tucker explaining something to the intended reader: connected,
   ordinary sentences; specific actions; contractions; enthusiasm without hype.
   Use a personal opening only when it fits, not a mandatory “I’ve been working
   on…” template.
3. Preserve meaningful uncertainty and technical facts. Remove transcription
   errors and redundant starts, not nuance. Do not sprinkle fillers or profanity
   into prose to manufacture a conversational voice.
4. Match the medium. Compact posts need a complete point; captions can explain
   more; scripts need room for visible action. Formal or sensitive correspondence
   should remain appropriate to its recipient rather than imitating a casual chat.
5. Keep essential privacy, attribution, installation and other factual limits
   readable in ordinary language. Voice editing must not hide qualifications or
   make a proposed demonstration sound already recorded.

## Check and return

- Does this sound like an explanation, or a product description with “I” added?
- Are there artificial slogans, metaphors, dramatic contrasts, or canned calls
  to action? Replace them with the specific thing being explained.
- Are uncertainties honest, and are first-person claims supported by the task?
- Are raw private examples being exposed? Use their phrasing lessons, not their
  account details, private subjects or full transcripts.
- Check actual character limits when applicable. For a script, label timing as
  approximate until a real read-through with the actions establishes it. Text
  samples do not establish speaking speed, pauses, accent or intonation.
- Return the revised draft in the requested format, with brief notes only where
  a meaningful choice or unresolved fact needs attention. Preserve artifact-first
  delivery when requested; do not bury the writing under a voice analysis.

Drafting is not authorization to send, schedule, publish, commit, or push.
Updating this shared reference requires an explicit request; do not silently
turn each phrasing correction into a durable preference or mine other threads.
