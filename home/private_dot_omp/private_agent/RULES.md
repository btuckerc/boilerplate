# Durable Safety Rules

- Never commit or push unless the user explicitly asks.
- Keep credentials and machine-local runtime state out of Git and chezmoi.
- Preserve unrelated user changes in dirty worktrees.
- Resolve destructive targets precisely; never use broad home, workspace-root, or unresolved-variable targets.
- The director (Codex Sol high here; Claude Code with Opus high is the primary director harness) owns requirements, integration and verification, and does trivial work directly. `task` runs on Codex Luna (parallel, no GPU queue): the default worker for delegated implementation, research and extraction with a clear contract and runnable check, including context >128K and images. `nous`, `scout`, `sonic`, commit and smol run on local nous Qwen to save Codex quota; use `nous` for small mechanical slices. `browser` for interactive web UI checks. Never delegate unresolved design to a worker.
- Escalate on evidence: unresolved high-consequence design, conflict after focused investigation, or a check that a focused repair did not move (same failure, or new failures in the repaired code). Clearly hard work may go straight up. Run `omp-quota` first. Use Sol (`architect` read-only at xhigh, `sol` implementation at high); it trails Astra slightly (DeepSWE 71.9 vs 74.1) at 1/5 the list token price and uses the Codex pool. Astra (`astra`) is a manual reserve: use it only when the user asks or a council seats it. OMP has no Anthropic models (Opus and Fable run only through Claude Code and `agent-run`). Skip any pool below 10% and say so.
- Spend paid legs on distinct questions, not repetition. Your own consult is one `architect`. Extra personas of the same model add correlated opinions, so use `scout` for further angles. A multi-model council runs only through the `council` skill on its trigger. Convene once per decision, never per loop iteration. In autonomous loops (hill climbs, sweeps), reruns, status reads and first attempts on a blocker go to the director, `nous` or `task`; `sol` gets a blocker only after a worker attempt fails, and another leg only while each leg makes progress (a narrower failure or new evidence); when one does not, stop and report it to the user.
- No routine planner or review tax for low-risk work. An explicit audit request, or a high-consequence control-plane, security, data-loss or cross-file integration change, needs one independent exact-candidate release audit (`auditor` through `/review` or `omp-audit`) before consequential apply, commit or publish. Architectural consultation (`architect`) and release assurance are separate decisions with separate allowances. On BLOCK, repair and re-audit the new candidate, with no round limit; read each round's findings. Fewer or narrower findings: keep going. Findings in code the last repair wrote: the approach is wrong, so redesign that part rather than patch it again. Findings at a steady count in new places: the candidate is too big for one audit, so split or simplify it. Stop and report only when a finding needs the user's decision or the remedy would drop requested scope. Only an accepted PASS on the exact candidate clears the boundary; an unresolved BLOCK or mandatory UNVERIFIED holds it. Neither audits nor tests grant commit or publish authority.
- Native desktop GUI stays inline with the director by default; a long multi-step GUI job MAY go to `sol` (OSWorld 2.0: GPT-6 Sol 60.5 vs Opus 5.5 48.7) with a screenshot of the end state as acceptance. DOM browser checks stay on `browser`.
- Children get a fresh scoped brief (owned files, contract, risky invariants, acceptance command, edge cases), not the transcript or a pre-solved answer. They return paths, checks, a short summary and blockers, never recurse, and stop at 30 minutes / ~100 requests. The parent verifies independently before accepting. `@slow` (Sol high) is for justified sustained frontier work.
- Supervise at natural checkpoints (`read proc://`; message with `write agent://<id>`; cancel with `write proc://<id>/kill`). Repair failed checks while each attempt makes progress; when one does not, reassess or escalate. Missing context, credentials or tools need prerequisites, not a bigger model.
- For a blocking local child, use eval `agent(..., {agent:"nous"})`, a finite handle wait and the parent check in one cell; keep the handle for cancellation. Use background task plus `wait` when there is parallel work.
- Task `effort` (on cloud models `med` means high and `hi` means max): omit it for ordinary implementation (agent default: medium, high for `sol`, xhigh for `architect`; always omit for `browser`, `architect` and `auditor`, where `med` would drop them to high). On `task` (Luna), pass `lo` for read-only exploration, extraction and summaries; `med` for subtle logic or after one failed check; `hi` only for hard debugging or substantive review. Local `nous` stays at its default.
- No compulsory classifier, swarm, transcript polling or advisor loop. Delegate only when the gain outweighs dispatch and verification cost.
- nous (vLLM) batches up to 8 sequences in one shared KV pool: run at most 4 local children at once. Never switch host services to delegate or silently fall back to paid inference.
- When interacting with Cloudflare, use the `cf` CLI unless the project has a Wrangler configuration file.
- Flag unverified claims in plain words ("unverified", "I expect", "not checked"), never as an `[INFERENCE]` tag: replies are read in chat apps, where the tag reads as noise.
