# Durable Safety Rules

- Never commit or push unless the user explicitly asks.
- Keep credentials and machine-local runtime state out of Git and chezmoi.
- Preserve unrelated user changes in dirty worktrees.
- Resolve destructive targets precisely; never use broad home, workspace-root, or unresolved-variable targets.
- The director (Opus medium) owns requirements, integration and verification, and does trivial work directly. `task` runs on Codex Luna (parallel, no GPU queue): the default worker for delegated implementation, research and extraction with a clear contract and runnable check, including context >128K and images. `nous`, `scout`, `sonic`, commit and smol run on local nous Qwen to save Codex quota; use `nous` for small mechanical slices when the GPU queue is idle. `browser` for interactive web UI checks. Never delegate unresolved design to a worker.
- Escalate on evidence: unresolved high-consequence design, conflict after focused investigation, or a check still failing after one focused repair. Clearly hard work may go straight up. Run `omp-quota` first. Use Sol high (`architect` read-only, `sol` implementation); it trails Astra slightly (DeepSWE 71.9 vs 74.1) at 1/5 the list token price and uses the Codex pool. Astra is a manual reserve: use it only when the user asks. Use `fable` only for a second opinion from a different model family after Sol fails. Fable costs about 2x Opus from your Anthropic pool. Skip any pool below 10% and say so.
- Spend paid legs on distinct questions, not repetition. A council is one `architect` (plus `fable` only under the rule above); extra personas of the same model add correlated opinions, so use `scout` for further angles. Convene once per decision, never per loop iteration. In autonomous loops (hill climbs, sweeps), reruns, status reads and first attempts on a blocker go to the director, `nous` or `task`; `sol` gets a blocker only after a worker attempt fails, at most two legs per blocker, then stop and report it to the user.
- For a high-stakes diff, MAY request one isolated critique from the other model family (`architect` for Opus-authored work): give it the diff, contract and check results, not the author's reasoning; allow one revision. Native desktop GUI stays inline with the director by default; a long multi-step GUI job MAY go to `sol` (OSWorld 2.0: GPT-6 Sol 60.5 vs Opus 5.5 48.7) with a screenshot of the end state as acceptance. DOM browser checks stay on `browser`.
- Children get a fresh scoped brief (owned files, contract, risky invariants, acceptance command, edge cases), not the transcript or a pre-solved answer. They return paths, checks, a short summary and blockers, never recurse, and stop at 10 minutes / ~40 requests. The parent verifies independently before accepting. `@slow` (Opus high) is for justified sustained frontier work.
- Supervise at natural checkpoints (`read proc://`; message with `write agent://<id>`; cancel with `write proc://<id>/kill`). Allow one failed-check repair, then reassess or escalate. Missing context, credentials or tools need prerequisites, not a bigger model.
- For a blocking local child, use eval `agent(..., {agent:"nous"})`, a finite handle wait and the parent check in one cell; keep the handle for cancellation. Use background task plus `wait` when there is parallel work.
- Task `effort` (on cloud models `med` means high and `hi` means max): omit it for ordinary implementation (agent default: medium, or high for `architect`/`sol`; always omit for `browser`). On `task` (Luna), pass `lo` for read-only exploration, extraction and summaries; `med` for subtle logic or after one failed check; `hi` only for hard debugging or substantive review. Local `nous` stays at its default.
- No compulsory classifier, swarm, planner, routine review, transcript polling or advisor loop. Delegate only when the gain outweighs dispatch and verification cost.
- nous serves one request at a time; parallel local children queue on the GPU. Never switch host services to delegate or silently fall back to paid inference.
- When interacting with Cloudflare, use the `cf` CLI unless the project has a Wrangler configuration file.
