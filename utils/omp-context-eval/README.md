# Native OMP context capture

`measure.py` runs the installed OMP 18.2.6 binary against a loopback
OpenAI-compatible endpoint. Each run gets a temporary `PI_CODING_AGENT_DIR`,
temporary HOME and synthetic cwd, a keyless loopback model, and one synthetic
user task. The endpoint returns a canned streamed response and records the
actual request body generated by OMP. No inference, cloud request, OAuth
database, session, `.env`, or user transcript is involved.

```sh
python3 utils/omp-context-eval/measure.py \
  --out /tmp/omp-context-20260919/native.json
python3 -m unittest discover -s utils/omp-context-eval -p 'test_*.py'
```

The four captured cases are isolated `xdev=true`/catalog with discovery disabled,
isolated `xdev=false` with discovery disabled, a standalone restricted-tool
current six-tool baseline (`read,grep,glob,edit,write,yield`), the unpromoted
three-tool candidate (`read,write,yield`), and the scoped
`read,edit,write,bash` set. The restricted-tool runs are not spawned task
children and provide no proof of task-child behavior; they are explicitly
labelled so they cannot be mistaken for one. The artifact separates exact
captured system text, tool-schema JSON, and complete wire-body token counts.
Default tokenization discovers the loaded local model on `nous` and uses its
`/tokenize` endpoint. `--tokenizer remote` fails closed if that exact counter is
unavailable; `--tokenizer estimate` is an explicit bytes/4 fallback.

The wire body is the actual provider serialization for this isolated fixture,
including OMP's rendered prompt and tool schemas. The production managed skill
tree and global discovery are intentionally excluded, so these are isolated
serialization baselines rather than full managed-context totals; that omission
is recorded in the JSON artifact.

The isolated passes do not establish a general tool regression: the native
Luna-to-nous payload was invalid in the separate acceptance attempt, and the
artifact scope is limited to these isolated request captures.
